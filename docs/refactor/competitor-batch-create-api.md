# 竞品批量创建

关联 #125，新增 `POST /api/v1/competitor/asins/batch-create`，要求当前主库 `asin:write`。返回 Legacy 信封、200、`Cache-Control: no-store`，data 包含 total、successCount、failedCount、results、errors。批量删除、导入、检查和监控继续单独迁移。

## 输入与结果

外层仅接受 `{ items: [...] }`，每批 1–1000 行，每个 SQL 插入块最多 100 行。空项或非数组保留旧 400 提示“items 不能为空”；超限及额外外层字段返回 400。行内容保留到业务层逐行校验，不能用单项创建的 schema 提前拒绝整批。

- ASIN trim 后大写，必须恰为 10 位 ASCII 字母或数字；国家 trim 后大写。品牌、名称及父组 ID 按旧规则转换字符串并 trim。父组取 `parentId || variantGroupId`。
- 类型接受 1/2、字符串 1/2、MAIN_LINK/SUB_REVIEW 及空值。父组国家需与归一化国家一致。
- 竞品不要求、不存储 site，也不对其执行数据库列宽检查；不伪造站点。新项为未断链、NORMAL、通知关闭，不继承父组通知开关。
- 按归一化失败、父组失败、已有重复、写入失败、成功的阶段返回完整结果；每阶段保持输入顺序。success 行含原始 index、生成的 id、asin、country、parentId；errors 只包含失败行。
- 父组查询使用 0010 的大小写/重音/尾空格等值规则，但随后保留 Legacy 批量服务按实际返回 ID 精确查 Map 的行为。仅大小写或重音等价的输入 ID 仍可能报告“所属变体组不存在”，这与单项创建的规范 ID 解析不同。
- 已有 ASIN 使用真实等值查询，再按旧归一化字符串 Set 判断。重音等价但字符串不同的已存键可能在写入阶段报告重复，保留该结果阶段。请求中的等价国家键保留输入靠前者优先创建。

## 事务与失败

复用 [竞品写入事务](./competitor-write-api.md)：主库当前账户、会话和权限锁一直保持到竞品业务提交后，业务只在独立竞品库执行，并要求 0010/0011 策略已就绪。仍为每实例最多 8 个操作、单条 SQL 1.5 秒及总操作 4 秒，不放大期限。

父组统一按规范 ID 排序加锁；唯一键按 PostgreSQL 实际 `neo_competitor_query_ci` 排序，相等键以原始 index 排序，避免交叉批次反序写入，同时保留旧逐行重试的胜出顺序。每次插入使用 SAVEPOINT，批插入的行级数据/约束错误恢复后逐项重试。只接纳 SQLSTATE 22/23 类及 P0001 为可恢复行错误；连接、超时、序列化和死锁等事务级错误使整批失败。父组时间仅在有成功项时更新，更新时间失败会回滚此前所有成功块。提交前验证完整响应计数。

与旧服务有两项有意收紧：无法转换字符串的 JSON 对象仅产生固定“参数格式无效”行失败；非业务重复的存储/驱动行错误固定为“创建失败”，不公开 SQL、约束或输入载荷。持久化文本按真实 Unicode 字符数限制，NUL 文本逐行失败，均不截断数据。

COMMIT 开始后未确认结果，沿用固定 503“写入结果未确认，请刷新数据后再操作”，应刷新核对，不能把该响应当作确定回滚并盲目重试。日志只记录固定操作与原因。

本批无新增 DDL。回退本批代码即可停用 Neo 批量入口，Legacy 保留；基础 0010/0011 的顺序和回退要求见基础写入文档。生产升级、最终同步及切流继续暂缓。

## 验证方式

VM 对照实际旧批量服务的归一化、完整结果、列值及默认通知；真实 Fastify 覆盖当前授权、Origin、外层边界、完整信封及响应计数。共享主营与导入测试继续执行，确认默认 site 规则不变。

Integration 使用实际 Legacy 控制器、服务及 MySQL DDL，在独立双 PostgreSQL schema 执行相同 HTTP 批次。先对齐每个原始输入的 UUID 生成序列，再精确比较完整 JSON 和所有业务列，不改写实际结果。验证混合阶段、ID 别名、重音重复、父组通知不继承、1000 行、100 行块后继续、真实 SQL 失败与 SAVEPOINT、最终更新时间失败、事务级错误回滚先前块、当前撤权、策略缺失、反序重叠批次及锁等待。新生成时间另检验更新/保留行为，不把时钟差当业务字段差异。
