# 竞品基础写入与双库授权事务

关联 #121。本批迁移五个实际端点，均要求登录、`asin:write` 和当前主库授权，返回 Legacy 信封及 `Cache-Control: no-store`；POST 成功仍返回 200。

| 方法 | `/api/v1/competitor` 下的路径 | 操作           |
| ---- | ----------------------------- | -------------- |
| POST | `/variant-groups`             | 创建竞品变体组 |
| PUT  | `/variant-groups/:groupId`    | 修改竞品变体组 |
| POST | `/asins`                      | 创建竞品 ASIN  |
| PUT  | `/asins/:asinId`              | 修改竞品 ASIN  |
| POST | `/asins/:asinId/move`         | 移动竞品 ASIN  |

删除、通知设置、批量操作、导入、变体检查和监控不在本批范围，Legacy 路径继续保留。

## 授权和事务边界

复用竞品查询的两连接生命周期：主库先取得共享管理锁，再锁定当前账户、会话并读取当前权限。只有授权成功才获取竞品连接，比较实际 `current_database()`，拒绝两个池连接同一个数据库。竞品事务执行全部业务查询、校验和写入，提交后才释放主库授权锁。守卫缓存不能代替事务内授权；`AUTH_DATA_AUTHORITY=legacy-mysql` 时返回 503，不回退旧写入。

每个查询或写入 repository 各自最多 8 个未真正结束的操作，总期限 4 秒，事务内单条 SQL 最多 1.5 秒。超时、取消和关闭会销毁借出的连接；迟到的池获取继续占用容量，获得连接后直接释放。repository 不关闭宿主连接池。

这不是分布式提交。竞品 COMMIT 开始前的失败可以终止未提交事务；COMMIT 开始后的错误、取消或主库连接失效，无法证明竞品写入是否提交。此时返回固定的 503 提示“写入结果未确认，请刷新数据后再操作”，客户端应先刷新核实，不能盲目重试创建。专用错误过滤器只公开这个固定提示；驱动错误、连接串和 SQL 不进入响应或日志。

## 行为和兼容边界

- 国家、ASIN 先 trim 再大写，并按转换后的 Unicode 字符长度校验。组名和品牌保留输入文本；禁止控制字符。组名最多 255、品牌 100、ASIN 20、国家 10、名称 500、ID 50 个字符。
- 公开 `asinType` 接受数字/字符串 1、2；Legacy 的 undefined、NULL、空字符串、0、false 都表示未设置。存储中的 MAIN_LINK/SUB_REVIEW 在返回时转换为 1/2，但不是公开写入值。
- 单个 ASIN 返回真实旧模型的完整 camelCase 记录，父键为 `variantGroupId`；不增加 `parentId` 或主营 site/人工状态字段，不继承父组品牌。通知 NULL 的展示值为 0，其他历史 NULL/D8 时间遵循已有编解码。
- 修改组国家会校验目标国家的等值重复 ASIN，并更新该组所有子项国家及时间；修改组品牌不改子项品牌，国家不变时不改子项时间。组返回最多 5,000 子项，超限在提交前返回 413，不截断或部分提交。
- 创建/修改 ASIN 要求国家与所属组一致。移动到同一组是完整无操作；跨国家移动拒绝；成功移动更新原组、目标组和 ASIN 的时间。
- 父组按 ID 的 C 排序锁定，再锁子项。等待父锁时 ASIN 已被其他事务移动，返回 409，避免覆盖新归属。所有显式更新时间在相关行锁取得后用数据库语句时间生成。
- ID 和重复 ASIN 查询沿用 0010 的大小写、重音、尾空格等值规则。通过别名找到父组后，保存其真实规范 ID，满足 PostgreSQL 外键；这修正了旧库可能保存输入别名、导致 JS 严格分组不一致的行为。现存重复校验保持旧 400；两个并发事务同时通过预检时由唯一索引保证只有一个提交，冲突返回 409。

## 升级与回滚

仅在竞品数据库、0010 比较规则已安装且最终旧数据导入完成后应用 0011。开发和 Integration 使用隔离数据；生产升级、最终同步和切流仍按独立部署安排执行。

```sh
corepack pnpm db:upgrade:competitor-write
```

升级取得两张竞品表的排他锁，验证 ICU 定义/版本，安装时间触发器及 ASIN/国家的 CI、重音、尾空格等值唯一索引。锁等待最多 5 秒，单语句最多 30 秒；重跑会重建本迁移专有索引，需要预留索引构建时间。现存等值重复记录会让整个升级事务失败，不合并或删除业务数据。

默认触发器仅在记录实际变化且调用方未修改时间时使用上海时区时钟；Neo 写入事务在核验真实触发器及唯一索引后设置事务级 explicit 模式，由每条写语句明确设置或保留时间。运行时持有表锁到提交，避免验证后 DDL 更换策略；触发器禁用、标记/比较规则不符或唯一索引缺失都返回 503，尚未修改任何数据。

回滚前停止或回退 Neo 竞品写入，再执行：

```sh
docker compose --env-file .env.neo -f compose.neo.yml exec -T timescaledb sh /opt/asin-monitor/apply-competitor-write-policy.sh /opt/asin-monitor/0011_competitor_write_policy.rollback.sql
```

回滚恢复 0000 时间触发器，删除 0011 专有函数和索引，保留记录及 0010 查询规则。函数删除使用 RESTRICT。必须先回滚 0011，再回滚其依赖的 0010。

## 验证方式

本地测试覆盖实际 Legacy 模型完整 JSON、输入边界、五个 Fastify 入口、当前授权和两连接生命周期。Integration 在一次性 MySQL 数据库执行原始控制器/模型/DDL，在独立主库与竞品 PostgreSQL 私有 schema 执行真实 HTTP 写入。逐键比较完整响应，生成 UUID 由两端测试 fixture 对齐；只有新生成时钟值容许小于 2 秒差异，覆盖 MySQL 秒精度和顺序请求耗时，历史时间、NULL 和未修改字段精确比较。

真实测试包含跨组唯一冲突、父锁竞争、撤权/会话变化、提交前授权持锁、父子写失败整体回滚、SQL 超时和恢复、取消、同库误配置、外键、子项超限、时间策略缺失及实际 COMMIT 成功后回执丢失。工作流重复执行升级和回滚；fixture 还验证升级遇重复记录时原子失败。隔离测试不代表生产迁移或实际规模验收已完成。
