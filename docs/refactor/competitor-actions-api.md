# 竞品删除与通知开关

关联 #123，在 #121 的同一竞品写入边界中新增四个端点。全部要求当前主库 `asin:write`，包括两个单项删除；`asin:delete` 是另外的批量删除权限，不在本批范围。

| 方法   | `/api/v1/competitor` 下的路径            | 成功 data         |
| ------ | ---------------------------------------- | ----------------- |
| DELETE | `/variant-groups/:groupId`               | `删除成功`        |
| DELETE | `/asins/:asinId`                         | `删除成功`        |
| PUT    | `/variant-groups/:groupId/feishu-notify` | 完整竞品变体组    |
| PUT    | `/asins/:asinId/feishu-notify`           | 完整单个竞品 ASIN |

四者均返回 Legacy 信封、200 和 `Cache-Control: no-store`，不存在记录保持真实竞品旧行为的 404。不能套用主营删除不存在记录仍成功的规则。ID 沿用 0010 的大小写、重音和尾空格等值查询，以规范 ID 执行 SQL。

## 数据和时间行为

- 删除组通过真实外键级联删除其 ASIN；竞品监控历史无外键，保留记录与历史快照。其他组和 ASIN 不变。
- 删除 ASIN 和更新父组时间在同一个竞品事务内执行。父组时间写入失败时，删除一并回滚。按父组、子项顺序取得行锁；等待期间 ASIN 被移动则返回 409，不删除新归属下的记录。
- `enabled` 只接受 true、false、0、1，字符串等其他值返回旧 400 提示。请求对象只允许 enabled 字段。
- 组通知开关仅更新父组的开关及时间，不传播到子项。单 ASIN 开关只更新该项的开关及时间，父组时间保持不变。即使开关值相同，仍按旧显式更新语句设置当前时间。
- 组通知修改必须在事务中取得完整响应；超过 5,000 子项或查询结果容量上限时失败并回滚，不提交未能返回的修改。删除返回固定字符串，不套用组响应子项数量上限；SQL 和操作总期限仍生效。

## 授权、故障与回滚

复用 [竞品基础写入](./competitor-write-api.md) 的主库当前账户/会话/权限锁、独立竞品事务、0011 策略探针、1.5 秒 SQL 期限、4 秒总期限及有界容量。权限缓存不能替代事务内复核，竞品库不保存账户，误连主库、策略缺失或数据库故障不会回退其他数据来源。

同样复用 COMMIT 开始后的固定 503 提示“写入结果未确认，请刷新数据后再操作”。这不是分布式提交；收到该提示应刷新确认，不能把失败响应视为一定回滚。

本批无新增数据库迁移；依赖既有 0010/0011，升级与回滚顺序见基础写入文档。回退本批代码停止四个 Neo 入口即可，Legacy 路径保留。生产迁移、最终同步和切流继续按用户安排暂缓。

## 验证方式

本地真实 Fastify 测试覆盖路由、asin:write、缓存后的撤权、Origin、输入和完整信封；Integration 加载原始 Legacy 控制器、模型和 MySQL DDL，在独立双 PostgreSQL schema 执行真实删除和通知操作。

实际数据用例比较完整通知/删除响应和错误消息，验证两边历史记录均不变化、真实 FK 级联、父更新时间失败回滚删除、子项删除失败回滚整个级联、等待期间移动冲突、当前撤权、disabled 策略与超限通知响应回滚。新生成时钟沿用 #121 的小于 2 秒精度容差；历史时间及所有未修改字段精确比较。共享事务和既有五个写入的测试继续保留。
