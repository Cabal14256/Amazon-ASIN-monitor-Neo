# 监控状态区间维护

关联：#109。状态区间保留每次状态切换的边界，用于异常次数、连续异常时长和时间轴；小时分桶不能代替这些语义。

## 数据维护

`0008_monitor_interval_projection.sql` 必须在最终 Legacy 快照导入以及 `0007` 之后执行。快照导入继续严格检查冻结基线中的 `varchar(50)`；运行时将区间键扩为 `varchar(53)`，容纳 `ID#` 加完整的 50 字符 ASIN ID。

- 历史记录的插入、删除，以及状态、时间、ASIN、国家、名称或变体组快照的修改，在同一事务内递增对应键的待处理版本。
- 只修改通知标记不会触发重建。变更 ASIN 或国家时，旧键和新键都需要重建。
- 首次升级登记已有历史和导入区间的全部键。重复执行升级保留已处理版本及未完成任务。
- 消费者在 `READ COMMITTED` 事务中用 `FOR UPDATE SKIP LOCKED` 领取一个键，按照完整权威历史重建，再提交已处理版本。区间替换和版本完成必须一起提交。
- 重建以检查时间和历史 ID 排序；连续同状态保留首条快照，同一秒内多次切换按旧系统写入规则保留最后一次。失败或回滚保留待处理状态。
- 区间表被直接修改或清空也会登记重建。禁止将跳过触发器作为普通写入方式。

消费者还记录每个键读取过的 Timescale 来源分块。保留策略删除整个分块时不会产生逐行删除事件；查询通过来源关系是否仍存在识别这种失效，消费者在普通待处理队列为空时重建这些键。

每次事务只重建一个键。调用方必须设置连接获取、语句、锁及整个事务的截止时间；超时销毁独占连接，不能将仍在工作的事务归还连接池。

## 查询选择

区间数据和可用性证明放在同一条 SQL 查询中，游标后续批次继续使用该查询的快照。证明检查：

- 维护版本已初始化；主表、来源分块和区间表的预期触发器存在且启用。
- 请求国家范围内没有尚未处理的版本，也没有已消失的来源分块。
- 起始时间不早于已有覆盖范围；结束时间不超过最后一次检查加 120 分钟。
- 不存在旧系统大小写不敏感主键与 JavaScript 状态键之间的历史身份冲突。

异常时长接口仅在起止时间都存在时尝试区间路径。条件不满足、维护尚未追上或相应数据库定义缺失时，读取原始分桶。连接故障、超时、容量错误不会被伪装成可用区间或空结果。

区间路径将空字符串和 NULL 快照都视为缺失；原始分桶路径保留旧接口仅对 NULL 回退的规则。两条路径分别与旧系统完整响应对照，不能只比较相同字段名或 SQL 行数。

## 升级和回滚

升级会在历史表上增加按国家和区间键检索的索引，并为已有键登记维护任务。脚本将锁等待限制为 5 秒、单条语句限制为 120 秒；大型数据集必须先在演练环境评估索引构建和首次重建时间，选择合适的维护窗口。超时应回滚整次升级后重试，不能跳过初始登记。

启用统计 API 前，需要完成独立维护消费者及其调度接入、权限和缓存验证、实际规模的积压恢复与延迟验收。单元测试和小型数据库对照不代表这些上线条件已经满足。

回滚顺序：停止区间维护生产者和消费者，回滚统计 API，再执行 `0008_monitor_interval_projection.rollback.sql`。回滚移除维护索引、函数、触发器和版本表，保留区间数据及兼容的 53 字符列宽，避免截断已经写入的合法 ID。再次升级会重新登记所有键。

如果运维曾禁用触发器、使用复制模式绕过触发器或手工替换来源表，必须在恢复查询前重新登记全部键。仅重新启用触发器不能证明绕过期间的数据已经被处理。

## 验证入口

本地类型检查和数据库构建从仓库根目录运行：

```sh
corepack pnpm --filter db build
corepack pnpm --filter db test
```

完整数据库对照由 Integration 工作流在明确授权的一次性 PostgreSQL / TimescaleDB / MySQL 环境执行。`monitor-interval-projection.integration.test.ts` 调用旧系统实际区间维护函数，覆盖状态切换、批次边界、晚到更正、删除、回滚、并发更新、分块删除和完整异常时长响应。需要数据库的本地跳过项不计为通过。
