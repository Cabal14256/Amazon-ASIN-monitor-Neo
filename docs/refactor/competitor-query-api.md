# 竞品变体组查询与双库鉴权

关联 #119。Neo 注册两个实际端点：`GET /api/v1/competitor/variant-groups` 与 `GET /api/v1/competitor/variant-groups/:groupId`，均要求登录及 `asin:read`，返回 Legacy 信封与 `Cache-Control: no-store`。竞品写入、导入、变体检查与监控继续各自迁移，不因查询入口完成而视为完成整个竞品域。

## 两个数据库的职责

主库持有账户、会话和权限。查询先在主库取得共享管理锁，再对账户、会话取得共享行锁，并从数据库重新读取当前权限；守卫的权限缓存不能代替这一复核。只有授权通过才获取竞品连接。竞品事务只读，并且比较两个连接实际返回的 `current_database()`，拒绝把两个不同池对象接到同一个数据库。

所有竞品表查询只在竞品连接执行。竞品快照提交后才提交主库事务，因此查询进行时的授权锁保持到数据读取完成。数据库错误、撤权、缺失表或错误连接配置都不会回退到主库竞品表或旧结果。该流程是跨库只读查询，不是分布式写事务；不复制竞品库中的账户或权限。

`AUTH_DATA_AUTHORITY` 尚为 `legacy-mysql` 时返回 503。实例关闭会取消其查询，应用最后统一关闭两个连接池。

## 结果兼容

- 保留关键词、国家、异常状态、分页、total、totalASINs、asin_count、完整 children，以及父项的下划线/驼峰字段。子项不增加主营特有的 site、人工异常或人工排除字段。
- 竞品有两套旧规则：查询筛选用“父项已标异常或存在异常子项”；返回展示状态只看子 ASIN 是否异常。因此一个已标异常的空组能命中 BROKEN 筛选，同时返回 NORMAL 展示状态。这是旧模型的实际行为，本次保留。
- totalASINs 按子项国家和子项异常状态筛选；组列表按父项国家与有效组状态筛选。asin_count 可以只统计关键词命中的子项，children 仍包含该页选中组的全部子项。
- `variantStatus` 只有精确 `BROKEN` 对应异常；其余非空字符串按 NORMAL 处理，空字符串不筛选。ASIN 类型 MAIN_LINK/SUB_REVIEW 映射为 1/2，其他未识别值保留为 NULL。
- 通知开关 NULL 的驼峰展示值默认为 0，父项原始下划线字段仍保留 NULL。历史创建/更新时间和子项 isBroken 的真实 NULL 已补入契约；D8 时间按现有上海时间编解码规则返回 ISO 字符串。
- 大小写、重音和尾空格等值查询使用 ICU 规则；关键词 `%`、`_`、反斜杠语义与冻结的 MySQL `utf8mb4_unicode_ci` LIKE 对照。PG16 不支持对非确定性规则直接使用 LIKE，所以复用 0007 已采用的逐字符匹配算法。
- 所有计数、选中组与子项在同一条 SQL 的 MVCC 快照内读取。创建时间相同时补充 ID 排序，使分页和子项顺序稳定；Legacy 在这些并列项上没有定义额外排序。

## 升级与回滚

查询启用前，**仅在竞品数据库**应用 `0010_competitor_query_matching.sql`：

```sh
corepack pnpm db:upgrade:competitor-query
```

升级创建并验证 `neo_competitor_query_ci`，建立有界 LIKE 函数，以及两个等值 ID 唯一索引和子项关联索引。已有等值重复 ID 会使整个事务失败，不会自动合并或删除数据。同名比较规则的定义/ICU 版本不同也会失败。

重跑会重建本迁移专有的三个索引，保证表达式和唯一性正确，不把同名对象视为已经通过验证。升级有 5 秒锁等待和 30 秒单语句期限；需要在部署前留出索引构建时间。它不修改业务记录、现有主键、外键、时间触发器或主库对象。

回滚时先停止或回退 Neo 竞品查询，再执行：

```sh
docker compose --env-file .env.neo -f compose.neo.yml exec -T timescaledb sh /opt/asin-monitor/apply-competitor-query-matching.sh /opt/asin-monitor/0010_competitor_query_matching.rollback.sql
```

回滚只删除本迁移的函数、索引和比较规则，保留记录；比较规则使用 RESTRICT，不级联删除外部依赖。Legacy 路径继续保留。

## 资源与失败边界

- 每个读取器最多 8 个尚未真正结束的操作，包含池获取；没有额外等待队列。总期限 4 秒（包含两个池的获取），单条事务内 SQL 1.5 秒。
- 超时、连接错误、取消或关闭会销毁两边已借出的连接。迟到的池获取继续占用容量，完成后直接释放，不能在授权锁已经丢失后执行竞品 SQL。
- 每页最多 100 个组、偏移最多 1,000,000、关键词最多 200 字符、国家最多 10 字符、组 ID 最多 50 个 Unicode 字符；参数无效返回 400。
- 完整子项最多 5,000，原始查询结果最多 32 MiB，超限返回 413，不截断响应。容量不足返回 429；其他数据库失败由全局 HTTP 边界返回安全错误。日志只记录固定操作与原因，不记录关键词、SQL、连接串或驱动载荷。
- 查询结果当前不使用 Legacy 的 60 秒列表缓存，返回数据库当前快照；这不能代替后续真实规模下的查询与缓存性能验收。

## 验证方式

本地测试直接加载旧竞品模型，核对完整列表/详情 JSON，并验证真实 Fastify 鉴权入口与读取器的两连接生命周期。Integration 在一次性 MySQL 数据库执行原始 DDL、模型及控制器，在 PostgreSQL 主库/竞品库的独立私有 schema 执行真实查询与授权竞争，比较完整 HTTP 结果。

覆盖空组计数、完整子项、父项筛选与子项展示差异、NULL/D8、通配符/重音/尾空格、相同 ID 主库假数据隔离、撤权和会话变更、跨库持锁、取消、SQL 超时与恢复、超过 5,000 子项，以及原始升级/回滚和重复 ID 拒绝。工作流重复升级和回滚；隔离 fixture 验证不代表生产数据或切流验收已完成。
