# P2 管理员重置密码

## 范围与启用

- `PUT /api/v1/users/:userId/password` 对应 Legacy 用户管理最后一个密码端点，返回 HTTP 200 的 message 契约。仍保留旧入口。
- 仅 `AUTH_DATA_AUTHORITY=postgresql` 可写；Legacy 权威模式返回 503。需要有效 Session、`user:write`，存在 Origin 时必须精确匹配 `CORS_ORIGIN`。ADMIN 角色不隐式免除权限校验。
- 管理员修改本人密码返回 400，继续使用个人中心。请求共用 `adminResetPasswordRequestSchema`；目标 ID 最多 50 个 Unicode 字符、不含控制符，新密码最多 1024 个 UTF-16 单元、不含 NUL，遵循共享复杂度策略。
- `forceChangeOnNextLogin`、`revokeAllSessions` 均默认 true，允许独立关闭。关闭会话撤销意味着旧 Session/JWT 仍可用；若强制改密仍开启，原会话仍受改密门禁。该行为沿用 Legacy，不自动提升撤销策略。

## 原子性与容量

- 服务最多同时接纳 8 次重置；bcrypt 使用已有全进程最多 8 次 CPU 工作限制、cost 10。新哈希在数据库锁外计算，随后开始独占事务。
- 与角色和用户管理使用同一全局 RBAC advisory lock，先锁操作者用户、Session 并重新读取权限/状态/密码策略，再锁目标用户。所有 Neo 管理写入必须遵循这个锁顺序。
- 目标行锁与本人改密共用，拿到锁后才校验当前密码和最近 5 次历史，不允许复用当前/最近密码，也不能与用户名忽略大小写相同。
- 直接复用 `DrizzleAccountUnit` 的历史保存/裁剪和密码更新；旧密码历史、bcrypt 哈希、改密时间、有效期、强制改密及可选全部会话撤销在同一事务提交。本人改密仍默认清除强制改密标记。
- `PASSWORD_EXPIRE_DAYS` 控制有效期，默认 90 天。重置不修改角色、账号状态或失败登录计数/锁定状态；解锁仍走用户状态管理。
- 获取连接受连接池超时限制，取到连接后事务总截止 2 秒、每条 SQL 最长 1.5 秒；失败/超时销毁独占连接，回滚全部写入。慢 bcrypt 无法被取消，但实际 CPU 完成前不会归还 CPU 容量，后续数据库操作也无法在已销毁连接上提交。
- 不更改角色缓存；鉴权会从 PostgreSQL 校验 Session 和用户密码策略。日志只记录正常业务事件或固定失败原因，不记录口令、哈希、原始异常或 SQL。

## 验证

- HTTP 测试覆盖鉴权/权限/Origin/权威门禁、输入、默认与可选策略、本人限制、历史拒绝、等待后撤权、脱敏和容量恢复。
- Integration 在已有认证管理测试的随机私有 schema 中运行真实 PostgreSQL/Redis、bcrypt、HTTP 和审计；验证旧 JWT 撤销、登录强制改密、历史裁剪、SQL 失败整体回滚、与本人改密并发、等待 RBAC 锁后撤权、目标行锁超时无迟到写入。
- 继续运行本人改密和用户管理回归，及仓库完整基线。根契约测试验证请求/导出 API 地址不产生重复 `/api`。
- 本地没有隔离 PostgreSQL 时跳过集成并明确记录；只有当前 head 的远端 Integration 实际执行通过才算数据库验收。

## 风险与回滚

- 无生产 DDL；回滚该提交即可移除 Neo 管理密码入口。已经提交的密码变化、历史和会话撤销不会因回滚代码复原，应通过受授权的账号恢复流程重新设置密码，避免恢复旧密码或复活被撤销会话。
- 不涉及生产数据同步、切流、旧系统退役或真实账号试改密码。该接口完成不代表 P2 阶段出口；D4 清理/归档调度仍需独立迁移验收。
