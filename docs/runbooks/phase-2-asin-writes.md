# P2 ASIN 与变体组基础写入

## 入口与部署前提

以下十二个基础写端点继续保留 Legacy 路径；新增的第十三个[批量删除写端点](./phase-2-asin-batch-delete.md)另述同步/异步执行和取消边界：

| 方法 | Neo 路径 | 行为 |
| --- | --- | --- |
| POST | `/api/v1/variant-groups` | 创建变体组 |
| PUT | `/api/v1/variant-groups/:groupId` | 更新组名称、国家、站点、品牌 |
| POST | `/api/v1/asins` | 在指定父组下创建 ASIN |
| POST | `/api/v1/asins/batch-create` | 批量创建并返回逐条结果 |
| PUT | `/api/v1/asins/:asinId` | 更新 ASIN 可编辑字段 |
| POST | `/api/v1/asins/:asinId/move` | 移动至指定父组 |
| DELETE | `/api/v1/variant-groups/:groupId` | 删除组及其子项 |
| DELETE | `/api/v1/asins/:asinId` | 删除 ASIN |
| PUT | `/api/v1/variant-groups/:groupId/feishu-notify` | 修改组通知开关 |
| PUT | `/api/v1/asins/:asinId/feishu-notify` | 修改 ASIN 通知开关 |
| PUT | `/api/v1/variant-groups/:groupId/manual-broken` | 组人工标记及全体子项历史 |
| PUT | `/api/v1/asins/:asinId/manual-broken` | ASIN 自身标记或组排除及历史 |

这些端点仅在 `AUTH_DATA_AUTHORITY=postgresql` 且完成[0004 时间策略升级](./phase-2-asin-timestamp-policy.md)后写入。保留最终 Legacy 导入 →0003→0004 的顺序。策略缺失、禁用或版本不符时返回固定 503，业务事务不提交；两个既有查询端点仍可使用。

删除需要 `asin:delete`，其余写操作需要 `asin:write`；两种权限分别判断，删除账号不额外要求写权限。HTTP 守卫检查登录和所需权限，随后在事务内复核当前账号、密码有效期、会话与相同权限。带 `Origin` 的请求须匹配 `CORS_ORIGIN`；无 Origin 的受控调用沿用现有接口策略。所有响应禁止缓存，成功状态保持 200 和现有信封，写入完成日志只在事务提交后记录。

## 兼容行为与输入

- 组创建允许相同名称/国家/站点/品牌，不引入额外业务唯一约束。组编辑仅改变组本身，不重写子项国家、站点或品牌。
- 删除保持幂等，缺失时仍返回 200 与`data: "删除成功"`。组删除通过真实外键级联子项，ASIN 删除在同一事务中触碰父组时间；已经缺失的 ASIN 不再触碰父组。监控历史和记录的名称/国家/结果快照保留。
- 通知开关仅接受布尔值或数值 0/1，不接受字符串。只改变目标实体的开关和修改时间；组开关不重写子项，ASIN 开关不触碰父组，不触发实际飞书发送。响应继续计算当前人工状态和历史元数据。
- ASIN 创建继承父组的有效人工状态，但不复制父组人工标记到自身字段；创建与父组更新时间触碰在同一事务。
- ASIN 编辑保留自身人工状态、排除信息、检查时间和父组 ID，也保留 Legacy 不触碰父组更新时间的行为。
- 移动保留 ASIN 国家、站点、品牌、自身人工及排除历史，仅改变父组及修改时间，并触碰源/目标组；移动到原组仍触碰时间。响应按目标组的当前人工状态计算，包括排除规则。允许组国家与子项国家不同，计数语义见[查询说明](./phase-2-asin-queries.md)。
- 类型接受数值或字符串 1/2，保存为字符串；未提供或 NULL 保存 NULL。名称为空字符串、NULL 或省略时保存 NULL；旧更新模型对省略名称可能传入 MySQL 不支持的 undefined，此处按现有可选契约明确清空。
- 请求对象最多 20 键，未知写字段拒绝；必填文本拒绝全空白和控制字符，接受的大小写与空白保持原样。按数据库字符语义计 Unicode 码点：国家 10、站点/品牌 100、组名 255、ASIN20、名称 500、ID 50；补充平面字符不会被错误减半。当前不模拟 MySQL 的全部重音/Unicode 排序规则，真实数据对拍仍须验收。

## 事务、并发和错误

### 批量创建

`POST /asins/batch-create` 接收 `{ items: [...] }`，数组长度 1–1000，空数组、非数组和额外顶层键返回 400。与单项创建不同，非法条目保留为逐条失败；只读取明确的业务字段，不写入条目中的额外字段。ASIN 去空白转大写且必须为十位字母数字，国家去空白转大写，名称/站点/品牌去空白，parentId 优先于 variantGroupId；类型还接受旧 MAIN_LINK/SUB_REVIEW。参数对象覆盖 toString 导致转换失败时，仅该条返回固定格式错误。

逐条校验顺序保持旧服务：ASIN、国家、站点、品牌、父组、类型、请求内重复。随后校验父组存在和归一化后的国家一致性（批量创建要求一致，单项创建沿用原有独立规则），再检查已存在的 ASIN/国家。响应 `results` 依次列出输入校验失败、父组失败、已有重复、插入失败、成功项，各阶段保持输入顺序；`index` 对应原始数组位置，不能将整个结果重新按 index 排序。即使所有条目失败，也返回 HTTP 200 和完整计数/逐条原因。

输入最多 1000 条，固定每批 100 条，不透传旧环境变量将分块无限放大。所有父组先按数据库 ID 排序锁定，插入按规范化 ASIN/国家排序，避免两个不同父组中的反序批次在唯一键上死锁；公开结果仍保持上述旧顺序。每个分块设保存点，数据/约束或明确行级异常时先回滚该保存点，再逐条重试；每条也有独立保存点。PostgreSQL 的失败语句不能像旧 MySQL 事务一样直接继续执行。

仅两个已知 ASIN 唯一约束错误返回重复提示；其余可恢复的行错误返回固定“创建失败”，不返回 SQL 或驱动详情。超过 PG 字符长度或含 NUL 的字段也作为条目失败，不截断数据。连接、超时、资源、死锁/事务冲突等错误终止整个请求，不降级为部分成功。成功子项与受影响父组时间在同一事务提交，仅触碰确实创建了子项的父组；父组时间或提交失败会撤销之前所有成功分块，返回固定 500。保留既有 2 秒总截止/1.5 秒 SQL 截止，超过截止需拆小请求重试。

批量创建使用当前自动正常状态与既有通知默认值，不复制父组人工字段，不生成监控历史，也不发送飞书。返回前在事务中验证共享响应契约和计数/条目总数。由于重复条目会报失败，网络结果不确定时先刷新查询并核对逐条结果，避免把重复错误当作新的创建成功。

### 人工标记与监控历史

组 `markedBroken` 接受布尔、数值或字符串 0/1。ASIN `action` 去空白转大写后接受 `MARK_BROKEN`、`CLEAR_SELF_MANUAL`、`EXCLUDE_GROUP_MANUAL`、`CLEAR_GROUP_EXCLUSION`；未知 action 可按有效 `markedBroken` 回退至自身标记/解除，保留旧兼容规则。新增自身标记和组排除必须有非空原因，原因按冻结契约最多 500 个 UTF-16 代码单元，保存前去两端空白。组解除忽略新原因，历史沿用解除前原因；ASIN 解除历史沿用已有有效原因或排除原因。

四种 ASIN 动作分别修改自身标记或排除状态，不改自动检查字段；即使父组尚未标记，也允许提前排除。旧模型从装饰后的自身/排除状态初始化八个字段，因此不活跃的历史排除元数据会在 ASIN 人工动作中清空；自身未标记但仍留存的原因等元数据按旧行为保留。ASIN 人工操作同时触碰父组时间。组标记不会更新子项行；组解除仅重置 `manual_excluded_from_group=true` 子项的排除字段及修改时间，其他子项（包括 false/NULL 的历史元数据）保留。

操作人来自事务内已锁定的当前用户行，优先 realName、username、id，禁止请求体指定操作人。自身/组标记字段按旧模型去空白并截取 100 字符；历史保持旧模型的回退规则。操作人和原因只进入业务数据与历史，服务日志不输出这些内容。

ASIN 操作创建一条 ASIN 历史；组操作创建一条 GROUP 历史以及每个子项各一条 ASIN 历史，包括排除、自身标记、自动异常和有效状态没有变化的子项。重复操作仍各自产生历史。记录保留名称、国家（含原大小写）、站点、品牌快照、前后有效状态、来源、人工范围及排除详情，使用现有 `monitor_history` 表，不增加 DDL。

在父组/ASIN 业务锁之后读取数据库操作时刻，人工标记时间、历史检查时间与 JSON 内对应时间使用同一毫秒时刻；通过现有上海时间 codec 保存，历史 create_time 显式赋值，避免旧事务开始时间默认值。业务 update_time 使用锁后的语句时钟，保留微秒顺序，hour/day/month 由数据库生成。

组完整前后快照最多 5000 子项；写前超界返回 413。历史每批最多 500 条，全部批次与状态、排除清理、父组触碰属于同一事务；任一批次或最终提交失败全部回滚。旧实现批量失败后逐条吞错、组调用忽略失败数会出现部分成功，Neo 明确修复这一行为；不降低原有事务/SQL 截止，也不把部分成功返回给调用者。

### 共享写事务

数据库事务使用 READ COMMITTED、共享全局 RBAC advisory lock 和当前账号/会话共享行锁。管理侧权限修改持排他锁，业务写等待后必须重新读取权限。策略准备函数持有两张业务表的兼容表锁，阻止触发器 DDL 在探针通过后插入事务，并开启仅本事务有效的显式时间模式。

业务行锁先锁父组、再锁 ASIN；多个组按数据库 ID 顺序锁定。更新/移动/ASIN 删除/通知/人工标记先读取候选源组，按序锁所需父组，再锁 ASIN 并复核所属关系。如另一个移动已经改变父组，返回 409 要求刷新，不在持锁途中改锁另一个未排序的源组。ASIN 删除等待期间若源组已级联删除，只有再次确认 ASIN 缺失才返回幂等成功；若仍存在则返回冲突，避免删除已移走的记录。组人工标记持父组锁贯穿前后子项快照与全部历史插入，后续监控处理器须遵循同一顺序。

ASIN/国家大小写重复由数据库唯一约束裁决，包括不同父组上的并发创建。只把两个已知 ASIN 唯一约束的 23505 映射为 409；其他数据库异常返回固定 500，不输出 SQL、参数或驱动对象。除幂等删除外，父组不存在/ASIN 不存在返回 404。缺少权限返回 403，非法输入 400，事务容量耗尽 429。API 最多 8 个本域写请求，仓储最多 16 个在途事务，沿用 2 秒事务总截止与 1.5 秒 SQL 截止。

响应在事务内构建，提交完成后才返回。组编辑与组通知开关需要返回完整子项，超过 5000 项时返回 413 并回滚组修改；插入、级联删除、父组触碰、移动或响应构建中任何失败均回滚整个业务事务。单个 ASIN 响应直接读取当前 ASIN 与父组，不因父组子项总数超过 5000 而截断或扩大读取。组删除不构建子项列表，但仍受 SQL/事务截止约束，超时整体回滚。

## 验证与回滚

本地参数测试用实际 Legacy 控制器对拍，响应与人工状态/完整历史测试直接执行实际 Legacy 模型，HTTP 测试覆盖十二路由、两种精确权限、当前授权、Origin、固定错误、容量及提交后成功。真实 PG/Redis 夹具显式安装外键、两个命名唯一约束/索引和 0004 触发器，覆盖重复创建、状态继承、父组时间、反向/竞争移动、幂等/级联删除、历史保留、删除/移动竞争、通知字段隔离、撤权等待、超界响应与故障回滚；不能用不含触发器的 LIKE 表代替实际写验收。人工事务另验当前操作人、全部传播历史、跨批成功、第二批失败时回滚前 500 条及排除清理、锁后时钟与移动竞争。

发布前运行根 17 项基线及 API 测试类型检查，并要求最新 CI/Integration 通过。正常回退本批 API 代码即可恢复使用 Legacy 入口；代码回滚不会恢复已经删除的业务数据或撤销已提交的人工状态/历史，需恢复时按事前备份与记录级核对流程处理，不能用旧快照覆盖已接收 Neo 写入的库。若需撤销 0004，必须先停止依赖它的写路径，再按时间策略运行说明回滚 DDL。当前未执行生产写入切换；导入、检查与其余业务 Worker 仍由后续批次迁移。
