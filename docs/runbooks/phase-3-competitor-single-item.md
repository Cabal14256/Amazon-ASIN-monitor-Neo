# P3：竞品 ASIN 单项管理

关联 Issue #163。Neo `/competitor-asin` 在原只读目录上开放竞品组创建、编辑、删除，以及子 ASIN 创建、编辑、移动、删除。Legacy 页面和生产入口保持原状；批量、导入、导出、通知切换与检查任务继续按后续阶段迁移。

## 权限与请求

- 路由仍要求 `asin:read`。创建、编辑、移动及单项删除组和子项均要求共享 Legacy 端点的 `asin:write`；仅有 `asin:delete` 的账号不能执行单项删除，该权限仍用于独立批量删除。Web 只显示当前身份允许的按钮，Neo API 守卫和主库授权事务均按相同权限复核。只读账号不能触发写入。
- 七个请求使用 `/api/v1/competitor/variant-groups` 与 `/api/v1/competitor/asins` 的单项端点及共享 Zod 契约。请求层统一归一化 `/api` 前缀；竞品表单不提交 `site`、人工异常或通知字段。
- 迁移返回的组/子项 ID 保留原始大小写、重音与空格（例如 `Gróup `、`Ásin `），详情和写入路径仅做 URL 编码，不 trim 或改写标识；快照、父组与移动目标字段也原样传送。空 ID、超过 50 个 Unicode 字符、控制字符与路径分隔符仍在请求前拒绝。
- 请求与下载共用的传输 URL 校验允许已编码的 `%20` 标识空格；仍拒绝原始路径空白、解码后的控制字符/DEL、编码分隔符、点路径和越出配置根目录的地址。
- 新增子 ASIN 默认使用父组国家和 ID；编辑子 ASIN 固定父组国家。竞品 ASIN 接受与 API 一致的 1–20 字符标识。移动目标按当前国家查找，提交前重新读取源组与目标组。服务端再次校验国家、归属和唯一约束。新组与子项的通知默认关闭，以服务端返回状态为准；本阶段不开放通知开关。

## 并发与失败处理

- 打开详情操作前重新读取详情，提交前再次比对源组/子项；删除组还比对成员 ID。编辑组、编辑子项和删除子项同时提交原始资料及更新时间快照；Neo API 在写入事务锁定对应行后再比较，发生并发编辑或移动即返回 409。移动提交 `expectedSourceGroup`，在父组和子项行锁全部取得后比较当前归属，再处理同目标组的无操作返回，防止页面读后另一管理员已移走的 ASIN 被再次移动。未携带快照的既有 API 调用仍沿用原行为。删除组的 `expectedChildIds` 和 `expectedSource` 对 Legacy 无请求体调用保持可选；Neo 页面始终提交原始组名、国家、品牌、更新时间及完整成员 ID 集，在锁定目标组后的同一事务中核对资料版本与成员，任一变化返回 409，保留当前组和全部子项。显式空数组表示确认组为空，不能等同于省略快照。
- 请求失败或用户取消不显示成功。401/403 清除当前目录快照并收起旧详情，重新核验身份和 `asin:read` 权限；仅失去写/删权限的账号可回到只读目录。
- 写入期间暂停筛选、分页和详情切换。写入请求发出前按用户与目录持久保存临时安全锁，并使用浏览器 Web Locks 串行化同账号跨标签的写入与核实；浏览器不支持 Web Locks 或本地存储不可写时拒绝写入。写入接口成功后重新读取列表及仍在列表中的已展开详情，读取完成才显示成功提示；如果所选组已被并发删除，则收起详情。刷新失败或写入结果未确认时清除旧列表与详情缓存，并保留安全提示；路由重进、浏览器刷新或重开后仍先核实。服务端明确在提交前拒绝的 503 保留目录与可修正的表单。无法确定是否创建成功的组或子 ASIN 即使重新读取了当前筛选页，也继续锁定目录写入，只允许筛选和查看，避免重复创建；操作员核实原记录后，可显式重新读取目录并解除锁定。不能据此断定当前页未显示的记录不存在。
- 本地存储不可用使用独立提示和“检查存储并恢复”入口，不伪装成新建结果未确认。恢复时重新检测存储并在跨标签锁内读取原安全状态；已有待核实操作继续保留，不能借存储恢复解除。尚无操作时重新读取目录后恢复写入。已发出请求的 `CANCELLED` 也视为结果未确认，清除旧列表/详情并保留持久化锁；取消浏览器等待不证明服务器回滚。

## 验证与回滚

- Web 服务测试覆盖七个请求契约与两种 `/api` baseURL，表单测试覆盖七项交互、字段差异、权限、撤权、刷新失败、路由重进、筛选页遗漏新记录和 403 后重新核验。API 测试覆盖删除权限的守卫、事务内复核及快照冲突；隔离数据库集成测试覆盖锁等待期间编辑组及读取后编辑、移动子项。运行 `corepack pnpm --filter web test`、`corepack pnpm --filter web lint`、`corepack pnpm --filter web build`、`corepack pnpm --filter api test`，并执行仓库基线。
- 联调时分别使用只读、仅写入和仅批量删除权限的账号，确认单项删除只按 `asin:write` 放行，再验证组/子项操作、并发修改、跨国家移动拒绝、刷新失败和 401/403。Neo 需 PostgreSQL 鉴权权威源及独立竞品库；默认 Legacy 代理下的 404/503 不代表真实数据验收。
- Review 回归补充：实际冻结的 Express 路由与 `checkPermission` 通过 HTTP 校验两个 Legacy 单项删除端点的写/删权限差异，仅会话身份、用户查询和业务删除使用替身；Neo Fastify 同时验证守卫及事务内当前 `asin:write`。API 验证 Legacy 无请求体 DELETE、可选空/非空成员集、组资料/更新时间快照和移动来源透传与冲突；DB 单测验证成员/来源快照在锁后生效；浏览器验证当前权限、初始存储拒绝、权限恢复、真实未决操作保留及取消写入后重进页面。真实 MySQL/双 PostgreSQL 集成用例覆盖无请求体级联删除、事务开始前已移走、锁等待中归属变化，以及成员不变时组名/国家/品牌/更新时间改变后的拒绝删除，刷新确认后允许删除。本地未启用隔离数据库时由设置 `RUN_INTEGRATION_TESTS=true` 的集成 CI 执行。
- 回滚 Web 提交可恢复竞品只读目录；若回滚 API 和契约，将失去 Neo 删除确认的事务内资料与成员比对，应同步关闭 Neo 页面删除入口，Legacy 无请求体调用保持原有 `asin:write` 契约。不涉及数据库迁移或生产切换。
