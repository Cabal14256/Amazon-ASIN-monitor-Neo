# P3：竞品 ASIN 单项管理

关联 Issue #163。Neo `/competitor-asin` 在原只读目录上开放竞品组创建、编辑、删除，以及子 ASIN 创建、编辑、移动、删除。Legacy 页面和生产入口保持原状；批量、导入、导出、通知切换与检查任务继续按后续阶段迁移。

## 权限与请求

- 路由仍要求 `asin:read`。创建、编辑、移动要求 `asin:write`；删除组和子项要求 `asin:delete`。Web 只显示当前身份允许的按钮，Neo API 守卫和主库授权事务均按相同权限复核。只读账号不能触发写入。
- 七个请求使用 `/api/v1/competitor/variant-groups` 与 `/api/v1/competitor/asins` 的单项端点及共享 Zod 契约。请求层统一归一化 `/api` 前缀；竞品表单不提交 `site`、人工异常或通知字段。
- 新增子 ASIN 默认使用父组国家和 ID；编辑子 ASIN 固定父组国家。移动目标按当前国家查找，提交前重新读取源组与目标组。服务端再次校验国家、归属和唯一约束。新组与子项的通知默认关闭，以服务端返回状态为准；本阶段不开放通知开关。

## 并发与失败处理

- 打开详情操作前重新读取详情，提交前再次比对源组/子项；删除组还比对成员 ID。发现记录已更新、移动或删除时停止提交，提示重新打开表单。此检查缩小误操作窗口；Neo API 事务再校验国家、归属和唯一性，预读与提交之间仍可能发生并发变化。
- 请求失败或用户取消不显示成功。401/403 清除当前目录快照并收起旧详情，重新核验身份和 `asin:read` 权限；仅失去写/删权限的账号可回到只读目录。
- 写入期间暂停筛选、分页和详情切换。写入接口成功后重新读取列表及仍在列表中的已展开详情，读取完成才显示成功提示；如果所选组已被并发删除，则收起详情。刷新失败或写入结果未确认时清除旧列表与详情缓存，并将安全提示保存在当前用户的查询缓存中，路由重进仍先核实。服务端明确在提交前拒绝的 503 保留目录与可修正的表单。无法确定是否创建成功的组或子 ASIN 即使重新读取了当前筛选页，也继续锁定本次会话的目录写入，只允许筛选和查看，避免重复创建；不能据此断定当前页未显示的记录不存在。

## 验证与回滚

- Web 服务测试覆盖七个请求契约与两种 `/api` baseURL，表单测试覆盖七项交互、字段差异、权限、撤权、刷新失败、路由重进、筛选页遗漏新记录和 403 后重新核验。API 测试覆盖删除权限的守卫和事务内复核。运行 `corepack pnpm --filter web test`、`corepack pnpm --filter web lint`、`corepack pnpm --filter web build`、`corepack pnpm --filter api test`，并执行仓库基线。
- 联调时分别使用只读、写入和删除账号，验证组/子项操作、并发修改、跨国家移动拒绝、刷新失败和 401/403。Neo 需 PostgreSQL 鉴权权威源及独立竞品库；默认 Legacy 代理下的 404/503 不代表真实数据验收。
- 回滚 Web 提交可恢复竞品只读目录。若需回滚 API，同步关闭 Neo 竞品单项删除入口，避免重新开放旧版 `asin:write` 删除授权；不涉及数据库迁移或生产切换。
