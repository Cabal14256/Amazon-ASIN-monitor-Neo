# P3：Neo 用户与权限页面

关联 Issue #147。Neo `/user-management` 接入用户管理、角色管理和权限控制三个页签。当前身份需具备 `user:read` 或 `role:read` 才能进入；每个页签及写操作仍按相应 `user:*`、`role:*` 权限单独控制。Legacy 入口和生产切流状态保持现状。

## 页面行为

- 用户列表由服务器按用户名、状态和页码筛选。可查看详情、状态历史、角色与权限；宽屏表格和窄屏卡片展示相同的关键字段，时间按上海时区呈现。
- `user:write` 可创建与编辑用户、重置密码；分配角色前必须成功读取当前可用角色。`user:delete` 可删除单个或批量用户，页面不提供删除当前账号的入口，并显示批量操作中的成功、跳过与失败数量及原因。服务器仍负责最终校验。
- `role:read` 可查看角色详情及按资源分组的权限清单；`role:write` 可保存角色权限。编辑前重新读取角色与权限定义，修改 ADMIN 角色需要额外勾选确认。
- 修改角色或当前账号后清空会话相关查询并重新验证身份；普通用户变更使管理查询失效并重新加载。密码仅存于临时表单状态，不写入 URL 或日志。
- 用户、角色和权限的六个 GET 响应设置 `Cache-Control: no-store`。前端遇到 401/403 后遮住已读取的敏感数据；只有拒绝发生后启动的读取成功才重新显示。400/401/403/404/409/429/503 和其他服务错误均提供可操作反馈。

## 验证与回滚

- Web 测试覆盖契约与 URL 前缀去重、读取与写入、密码 URL 边界、分页校验、撤权后旧数据遮蔽、路由和导航权限。API 测试验证六个 GET 的 `no-store`。执行仓库完整基线及 Web typecheck。
- 隔离环境回归建议使用具备不同权限的真实账号，检查撤权/会话失效、角色变更后重新验证、批量删除部分失败、状态历史、宽窄屏和长字段。若本机浏览器连接限制仍在，需在 PR 记录视觉验收未执行原因。
- 回滚此 PR 可恢复 `/user-management` 占位页及导航状态，并撤销六个 GET 的缓存头；不涉及数据库、Legacy 实现或生产代理。Neo 用户权限 API 是否可用仍由现有 `AUTH_DATA_AUTHORITY` 阶段配置决定；生产迁移维持暂停。
