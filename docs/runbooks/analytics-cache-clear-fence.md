# Neo 分析缓存清理与部署

`POST /api/v1/ops/analytics/cache/clear` 仍要求当前 `settings:write` 权限。成功响应表示本次有限扫描完成，并且 Redis 原子代际比较交换已确认成功；在清理前获得的查询租约不能在成功响应后重新填充旧结果。分析数据事务仍使用 `BEGIN READ COMMITTED`，此变更不提供跨查询的可重复读快照，也不替代分析数据更正后的完整失效流程。

## 控制状态与读取

- 数据键继续使用 `<BULL_PREFIX>:neo:analytics:v1:<hash>`；键名保持兼容，内容改为带代际的 v2 envelope。旧 v1 内容成为冷缓存。
- 代际键为 `<BULL_PREFIX>:neo:ops:analytics-cache:generation`，位于数据扫描范围之外，值为 32 个随机字节编码成的 64 个小写十六进制字符，无 TTL。缺失时原子 NX 创建。已存在的错误类型、错误长度、带 TTL 或非十六进制值不会被自动修复。
- 缓存读取在数据 SQL 执行前，以一次 Lua 调用取得代际租约与最多 2 MiB 的内容。回填只能使用该租约，Lua 比较失败时不写入数据。Redis 不可用或租约无效时读取数据库，并跳过回填。
- 保留每实例最多 4 条尚未真正结束的底层缓存命令、每次调用 500 ms 预算、原 TTL、绕过缓存与完整数据校验。调用方超时不会取消已发送的 Redis 命令；槽位直到命令实际结束才释放。

## 清理返回结果

授权事务提交后，清理取得旧代际及 Redis `TIME`，最多扫描 100 页、10,000 个数据键，以 200 个键为一组 `UNLINK`。前缀按字面值过滤，即使配置含 Redis glob 字符也不能扩大删除范围。

从首次捕获前开始，共享一个 5 秒单调时钟预算。每次发命令前和收到响应后都检查该原始预算。首次捕获响应到达后，以服务端起始时间 S0 加上此时本地剩余时间 R，固定最终 Lua 的服务端截止时间。后续扫描、响应延迟或重试均不重授这段预算。最终 Lua 在截止时间之后实际执行时拒绝修改；在截止时间内执行成功但响应丢失时，修改可能已经发生。

- **200**：最终 Lua 确认旧代际仍匹配，原子写入新的随机代际与 `last-cleared-at`（30 天 TTL），并在本地原预算内收到确认。
- **409**：扫描超过限制，或已知另一清理操作先完成代际交换。重新发起请求重新捕获当前代际；不能重发旧交换参数。
- **503**：Redis、控制状态或时间预算异常。扫描/删除阶段失败，以及已知最终 CAS 冲突，不会旋转已有代际。最终命令可能已执行而确认丢失或过晚时，结果为未知，代际及清理时间可能已更新。系统不会回退代际，不会把调用方超时当成 Redis 撤销。

失败过程中已经完成的 `UNLINK` 不会恢复，缺失的代际键可能已经初始化；这类失败不应解释为所有 Redis 状态均未改变。重新请求可产生新代际，旧请求即使迟到也不能让代际回到以前的值。概览中的 `last-cleared-at` 是服务端已执行的记录，不单独证明某一客户端收到了 200。

## 升级、回滚与运维

1. 升级所有使用同一 `BULL_PREFIX` 的 API 实例，排空旧进程与旧在途请求，再执行清理。旧二进制忽略代际 CAS，混跑期间不具备本保证。
2. 代际控制键需要持久保留，不应由数据清理任务或 TTL 管理删除。控制键损坏时先排空流量并检查 Redis，按维护流程处理；产品不会自动覆盖异常控制值。
3. 回滚需要排空新实例并丢弃 v2 缓存数据，让旧实例从数据库重建。此变更没有 PostgreSQL 迁移，不需要数据库结构回滚。
4. Redis 快照恢复到旧代际、跨节点时钟异常或服务端时钟回退属于维护事件，不在普通清理的截止时间保证内。恢复后先排空请求、清空分析数据缓存并重新初始化代际，避免恢复旧租约。

日志只记录固定原因、删除条数等最小运行上下文，不记录代际值、缓存键、原查询、权限载荷或个人数据。

## 验证范围

原实现的四个业务 oracle 保留：两条迟到 SQL/迟到 SET 回归断言，以及正常独立实例填充命中、普通清理后新结果填充命中两个健康对照。授权失败由既有运维测试另行覆盖。内存 Redis port 仅模拟状态转换，不声称执行了 Lua。控制预算单测验证慢捕获响应、固定截止时间和超时后底层工作仍可能继续。

现有被 Integration workflow 选中的 `monitor-analytics.integration.test.ts` 增加真实 PostgreSQL、真实 Redis、两个独立 API 实例及有限 RESP 传输门闩：授权已提交后再挂起真实 SQL 结果、迟到回填实际执行 CAS、最终 Lua 超过服务器截止时间才执行，以及真实执行成功但确认丢失。原生用例仅允许显式集成开关与已确认的可丢弃本地 CI PostgreSQL/Redis 目标；具体执行结果以对应提交的日志为准。
