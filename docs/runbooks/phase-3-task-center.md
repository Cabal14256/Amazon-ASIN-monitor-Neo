# P3：Neo 任务中心

关联 Issue #139。Neo `/tasks` 使用现有任务客户端与 Query hooks 展示当前登录用户的任务列表、详情、进度和确认取消。路由继续沿用真实身份守卫，强制改密时仅开放个人中心；Legacy Tasks 页面及生产入口保留。

## 行为与边界

- 列表读取 `GET /api/v1/tasks?status=all|active&limit=100`，详情按任务 ID 读取，使用 40 MiB 有界响应以容纳最多 32 MiB 的检查结果及 HTTP 信封。WebSocket 任务消息使相应 Query 失效，进度消息批量合并；列表每 15 秒兜底读取，进行中详情每 1.5 秒读取，终态停止高频轮询。断线后页面仍可手动刷新。完成/取消消息显示短暂通知。
- 只显示服务端明确返回的任务摘要、有限数量的警告、错误样本和计数，不将未知 `result` 整体序列化到页面。批量检查的失败样本即使已被服务端截为 20 条，也按 `failedCount` 显示截断提示。全部视图最多显示最近 100 条，数量不是任务总数；服务端仍按当前本人身份和任务 owner 鉴权。
- `canCancel` 必须为真且任务处于等待/执行中，并属于当前 Neo 取消 API 支持的任务类型，页面才出现确认取消。变体检查虽可能在序列化时标记 `canCancel`，当前取消 API 不支持它，因此不显示误导操作。取消成功或失败后重新读取服务端状态。
- 下载对已完成、带有效报告引用的主营/竞品导入任务、有效变体/批量检查结果，以及受支持的 `export/asin` XLSX 显示。已完成的检查任务详情与下载、ASIN 导出下载还需当前身份具备 `asin:read`；API 每次读取仍重新鉴权。浏览器经统一 TaskApi 使用当前账号 Cookie 或 Legacy Bearer，读取文件有 256 MiB 上限，不使用返回的 URL 拼接或 Token 查询参数。过期或损坏文件仍由 API 返回错误。
- ASIN 导出后台处理或自动等待超时后，可回到任务中心下载。入口校验 completed、export/asin、任务绑定的 artifact key/大小/SHA-256、XLSX MIME、公开文件名与回执一致，并使用 `ASIN数据_YYYY-MM-DD.xlsx` 保存，避免把工作簿误命名为检查 JSON。实际下载后核对 MIME 和长度；存储中的文件完整性、所有者和当前 `asin:read` 仍由 API 校验。页面不接受返回的任意文件路径或其他导出类型。
- 下载期间用户、session、读取权限或强制改密状态变化，以及离开页面，都会中止本地传输；迟到的响应不会创建 object URL 或触发下载。文件失效和 403 显示错误，不自动重试，用户可在核实后显式再次下载。主营/竞品导入与检查 JSON 的原有文件名和路径保持兼容。
- 检查结果详情可达 32 MiB；关闭或切换任务后，详情 Query 立即回收，避免连续查看多个任务时缓存累积。列表与当前打开的详情仍按既有轮询和 WS 提示更新。
- 本页面消费既有 ASIN 导出任务；相关生产者与文件完整性验证见 `phase-2-asin-export.md`（Issue #166 / PR #172）。其他导出和备份仍按后续阶段接入，不做生产流量切换。

## 验证与回滚

- Web 测试覆盖任务操作资格、结果展示边界、URL 归一化、WS/轮询查询失效、路由权限；执行 Web test/lint/typecheck/build 与仓库基线。联调建议用本人及他人任务检查权限、真实 WS 推送、取消竞态、移动端布局、已完成文件与过期文件。
- 回滚本 PR 即恢复 `/tasks` 占位页与导航状态，不涉及数据库、Legacy 或生产代理。浏览器视觉验收若本机连接限制未解除，需在 PR 中记录未执行原因。
