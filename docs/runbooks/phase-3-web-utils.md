# P3-T2：Neo 前端兼容工具

关联 Issue #37。按总体计划原样迁移 `beijingTime.ts`、`peakHours.ts`、`amazon.ts` 到 `apps/web/src/lib/`，保留旧文件名、导出和输入语义。此批不包含页面、图表、路由或生产切换。

## 时间解释

`toBeijingDayjs`、`formatBeijing`、`formatBeijingNow`、`formatBeijingDate` 使用命名时区 `Asia/Shanghai`。符合旧格式的无偏移时间字符串按上海墙钟解释；带 `Z` 或偏移的字符串、Date、时间戳、Dayjs 按对应时刻转换。空值、空字符串和纯空白字符串沿用“当前时间”，不会被当成非法日期。

日期处理不是表单校验器；默认输出精度为秒，调用方可指定格式。新表单必须在调用工具之前检查必填项及日期合法性，不能把空输入自动显示为当前时间当作验证通过。

Neo 显式依赖与根 Legacy 一致的 `dayjs@1.11.19`，复用根 lockfile 已存在的包，不升级 Dayjs 或修改后端时间转换。数据库 D8 的存储/读取约定仍是独立门槛，前端格式化不能修复错误的数据库时刻。

## 峰值时段和统计

六国仍按北京时间划分，开始小时包含、结束小时不包含：US 02–06/09–12；UK 22–24/00–02/03–06；DE/FR/ES/IT 20–24/02–05。国家代码保持大小写敏感；未知国家的峰值区间为空、`isPeakHour=false`、`isOffPeakHour=true`。

`getTimeRangeStats` 保留旧的小时格计数：先把开始时间向下取整到小时，逐小时递增，**包含等于结束时间的小时**。这不是连续时长积分，也不按半开时间范围统计。例如 01:30→02:00 计两格；00:00→ 次日 00:00 计 25 格。开始和结束在同一小时内，即使输入倒序，也可能因开始取整而计一格。

函数没有对范围作大小/顺序验证，复杂度随小时格数增长。后续页面须先验证有序且有界的范围，不向主线程传入任意超大跨度。若要改为时长积分或有界算法，须另行明确兼容性变更；本批不悄悄改写旧结果。

## 商品链接

保留全部 21 个旧站点映射，并非仅六个监控国家。站点参数有效时优先于国家，移除 HTTP(S) 前缀和首个斜杠之后的路径，最终使用 HTTPS；无有效站点则按国家映射，无 ASIN 或无法确定站点时返回空字符串。

旧 helper 支持自定义域名、原样拼接已 trim 的 ASIN，不是 Amazon 域名白名单、ASIN 编码器或安全 URL 校验器。本批只移植链接构造，不进行网页访问。后续消费它的页面应验证 ASIN/受信站点配置；不能把任意用户字符串送进此函数后当作已验证链接。
